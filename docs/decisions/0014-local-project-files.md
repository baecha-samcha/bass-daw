# 0014 — 클라우드 동기화 대신 로컬 .dawbae 프로젝트 파일

2026-10-23 · 사용자 요청으로 적용. D1/R2·인증 공급자 연결 계획을 현재 배포 범위에서 제외한다.

- 활성 앱의 클라우드 UI/초기화/폴링을 제거한다. API 환경변수를 넣어도 활성 앱에서 동기화를 시작하지 않는다. 이전 API·SyncEngine 및 관련 도메인 테스트는 과거 구현 보존을 위해 남기며 배포하지 않는다. 이전 클라우드 UI e2e는 `tests/legacy`로 옮긴다(현재 기능의 PASS로 세지 않음).
- 저장 파일 확장자는 `.dawbae`. 기존 ZIP 컨테이너(`archiveVersion:1`, manifest.json/project.json/assets/<sha256>)와 프로젝트 스키마는 유지한다. 이전 `.bassdaw` 가져오기 지원. 기존 프로젝트 파일은 열 때 독립 복구 사본으로 만들어 원본 ID의 프로젝트를 덮어쓰지 않는다.
- 파일 저장은 현재 immutable Project를 직접 묶어 브라우저 recovery commit 지연·quota에 의존하지 않는다. 개인 로컬 파일에는 원본 음원·녹음과 라이선스 메타데이터를 포함한다(재배포 허가를 의미하지 않음). 원본 bytes가 없으면 파일 생성을 거절한다. 다른 배포 목적 exportArchive의 기존 재배포 금지 자산 제외 정책은 유지한다.
- File System Access 지원 시 최초 저장/다른 이름 저장은 picker를 사용자 제스처 안에서 호출한다. 성공 후에만 handle을 연결한다. 후속 Ctrl+S/저장은 그 파일을 갱신한다. `.bassdaw` handle에는 새 확장자로 Save As를 요구해 옛 파일을 보존한다. handle은 세션 내에서만 유지한다.
- 미지원 브라우저는 `.dawbae` 다운로드. OS 쓰기 완료를 관측할 수 없으므로 상태를 '파일 다운로드 요청됨'으로 표시하고 완료는 브라우저에서 확인하도록 한다. picker 취소를 다운로드로 우회하지 않는다.
- write/close 실패 시 abort를 시도하며 저장 성공/sequence를 갱신하지 않는다. 쓰는 동안 새 편집이 생기면 저장된 sequence와 현재 sequence 차이로 '파일 미저장'을 표시한다. 파일 이름·상태·오류는 브라우저 복구본 상태와 별도로 관리한다.
- 브라우저 자동 저장·lease/epoch fencing·복구·Undo·재생·기보는 유지한다. 기기 복구본을 컴퓨터 파일에 저장한 것처럼 표시하지 않는다. Ctrl+S=파일 저장, Ctrl+Shift+S=다른 이름 저장. 파일 기반 문서에서 파일 미반영 변경/쓰기가 있으면 beforeunload 경고를 요청한다(표시 여부는 브라우저 정책에 따름).
- Workers 배포는 웹 정적 자산만 필요하다. D1/R2·로그인·클라우드 세션·동기화 API는 사용하지 않는다. 프로젝트 저장/공유는 사용자가 로컬 파일을 옮기는 방식이다.
