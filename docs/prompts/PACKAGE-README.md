## 사용 방법

이 폴더 전체를 Raspberry Pi로 옮긴 뒤, 아래 프롬프트를 한 번에 하나씩 Codex 또는 Claude Code에 실행하도록 전달해 주세요. 앱 저장소 안이나 옆에 두어도 됩니다. 각 프롬프트는 해당 단계에 필요한 공통 작업 지침을 자체 포함하고, 상세 계약은 동봉 `specs/`를 참조합니다. 과거 채팅 내용이 없어도 사용할 수 있습니다.

처음 전달할 문장 예시:

> `bass-daw-mvp-prompts/prompts/MVP-00-environment-probes.md`와 동봉 참조 명세를 읽고, MVP-0 범위의 구현과 검증을 진행해 주세요. 실제 저장소 상태를 확인한 뒤 기존 작업을 보존하면서 이어 주시면 좋겠습니다.

단계가 끝나면 `docs/reports/MVP-N-report.md`의 결과와 실제 사용자 확인 흐름을 검토한 뒤 다음 파일을 실행하도록 전달해 주세요. 여러 파일을 한꺼번에 전부 실행하도록 지시하지 않는 것이 좋습니다. 에이전트 컨텍스트가 바뀌면 최신 보고서와 해당 단계 파일을 다시 읽도록 전달해 주세요. scp 명령은 이 패키지에 포함하지 않습니다.

MVP-0은 실험, MVP-1~4는 기능 누적 단계입니다. **MVP-5가 첫 개인용 베타**이며 MVP-6/7은 각각 플러그인과 클라우드 확장입니다. MVP-6과 MVP-7은 서로 독립적이지만 같은 작업 트리에서 동시에 수정하도록 지시하지 않는 것을 권장합니다. 본 패키지는 병렬 에이전트 실행을 요청하지 않습니다.

## 승인·미정 항목의 처리

00 개발 계획은 사용자가 검토하여 방향을 승인했습니다. 본 패키지는 그 방향을 MVP 작업 단위로 나눈 지시서이며, 이 문서를 만드는 현재 작업에서 앱 코드를 구현한 것은 아닙니다. 특정 단계 실행을 에이전트에게 요청하면 그 단계 범위의 구현을 진행하도록 구성했습니다. 동봉 원본 명세의 작성 당시 ‘구현 전 검토안’ 표기는 이 구체적인 실행 요청을 무효화하지 않습니다.

D01~D06 설계 기본안은 단계별 구현 기준으로 사용하며 확정 스택과 충돌하면 변경 제안을 먼저 제시합니다. D07/08의 실제 모바일 기기·로그인 공급자·도메인·음원 라이선스·예산·한도는 선택이 남아 있습니다. 필요한 시점에만 확인하고 관련 없는 로컬 구현은 이어 가도록 했습니다. 인증 공급자나 production 계정 정보를 임의로 만들어 넣지 않습니다.

## 명세와 결과 보관

- `specs/`: 작성된 상세 명세 스냅샷 6개. 이번 패키지용으로 내용은 변경하지 않았습니다.
- `prompts/`: 단계별 독립 작업 지시서 9개.
- `docs/reports/MVP-N-report.md`: 구현 에이전트가 실제 저장소에 생성할 결과 보고서입니다. 현재 패키지에 이미 실행된 보고서가 들어 있는 것은 아닙니다.
- 구현 완료/자동 테스트 통과/실제 장치 게이트 통과를 구분합니다. BLOCKED와 NOT-RUN을 PASS로 간주하지 않습니다.

보고서를 이 대화에 전달하면 명세 충족 여부와 다음 단계 진행 가능 여부를 검토할 수 있습니다.
